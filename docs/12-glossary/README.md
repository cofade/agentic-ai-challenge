# 12. Glossary

| Term | Definition |
|------|------------|
| **Agentic** | An LLM-driven system in which the LLM (the *agent*) decides the next action — including which tool to call — based on the current state. Distinguished from a hardcoded "prompt chain" where the developer specifies the call sequence in advance. |
| **ADR** | Architecture Decision Record. A short, immutable document capturing the context, decision, and consequences of a non-trivial architectural choice. See [`../09-architecture-decisions/`](../09-architecture-decisions/). |
| **arc42** | A documentation template for software architectures with twelve numbered sections (introduction, constraints, context, solution strategy, building blocks, runtime view, deployment view, concepts, decisions, quality requirements, risks, glossary). This project uses sections 1, 5, 6, 9, 11, 12. |
| **BM25** | Best-Matching 25, a classical sparse-retrieval ranking function based on term-frequency / inverse-document-frequency with length normalisation. Strong on keyword anchors (e.g., error codes). |
| **Chunk** | A unit of retrievable text. In this project, chunks are individual sentences with provenance metadata (source path, position, language). |
| **ClaimEvidence** | Per-claim record produced by the reason agent: `{chunk_id, quote}`. The verifier evaluates each ClaimEvidence individually. The reason agent's layer-1 defences reject ClaimEvidences with fabricated `chunk_id`s or quotes that are not substrings of the cited chunk before they ever reach the verifier. |
| **Clarify path** | One of three canonical runtime paths through the LangGraph state machine. Triggered when the triage agent detects missing critical metadata fields; the supervisor routes to the clarify worker, which generates 2–4 targeted follow-up questions. The retriever is not called on this path. See [`../06-runtime-view/ticket-flow.md`](../06-runtime-view/ticket-flow.md). |
| **Confidence** | A 0–1 score on the system's own output. Computed as `min(rubric_score, verifier_score)` whenever the verifier ran (solve sink *and* downgrade-clarify sink); `rubric_score` alone on the missing-fields clarify sink where the verifier never ran. Routing is determined by the LangGraph topology (triage gaps → clarify; grounding score < 0.4 → downgrade); the confidence value is informational output. See [ADR-007](../09-architecture-decisions/ADR-007-confidence-quantification.md). |
| **Coverage case** | A semantic label on each eval-set ticket recording what scenario it exercises (e.g. `resolvable EN`, `clarify missing OS`, `ungrounded claim trap`). The eval harness reports per-coverage-case accuracy alongside the aggregate metric, so a single low aggregate cannot mask which scenarios actually broke. Defined in `tickets/eval_set.json`; see [ADR-010](../09-architecture-decisions/ADR-010-evaluation-harness.md). |
| **Downgrade path** | The runtime path taken when retrieve and reason produced a draft solution but the verifier's aggregate grounding score falls below 0.4. The supervisor routes to a `finalize_clarify_downgrade` sink that emits a clarify-shaped Output with the ungrounded claims listed in `preliminary_assessment` — rather than routing back through the clarify worker, whose gap-matcher would reject this case. See [ADR-008](../09-architecture-decisions/ADR-008-groundedness-gate.md). |
| **Eval set** | The 16-ticket hand-labeled set at `tickets/eval_set.json` used by the eval harness. Each ticket has expected category, expected priority, expected `should_clarify`, and a coverage case label. See [ADR-010](../09-architecture-decisions/ADR-010-evaluation-harness.md). |
| **Grounding** | The property that every claim in a proposed solution is supported by an explicitly cited KB chunk. Enforced by the verifier agent. |
| **KB** | Knowledge Base. The local Markdown corpus that is the *only* authoritative source of facts the system may rely on. |
| **LangGraph** | A library that builds stateful agent graphs over LangChain primitives. Used here for the supervisor + workers topology with explicit state transitions. |
| **Ollama** | A local LLM runtime that serves open-weight models behind an HTTP API ([ollama.com](https://ollama.com)). The default LLM provider for this project per [ADR-004](../09-architecture-decisions/ADR-004-llm-provider-abstraction.md); tested with `gpt-oss:20b`. Allows the pipeline to be run offline with no API account. |
| **RAG** | Retrieval-Augmented Generation. The pattern of retrieving relevant context from a corpus and injecting it into an LLM prompt to ground generation. |
| **Reasoning trace** | An ordered list of `ReasoningStep` records, one per agent action, recording the actor, the action, the evidence references, and the rationale. Visible in both JSON and text outputs. |
| **RRF** | Reciprocal Rank Fusion. A method to combine multiple ranked retrieval lists by summing the reciprocals of their ranks. Avoids the pitfalls of score normalisation across heterogeneous retrievers (e.g., BM25 vs cosine similarity). |
| **Rubric** | The weighted-component formula that produces `rubric_score`: `w_ret × retrieval_quality + w_meta × metadata_completeness`, clamped to [0, 1]. `retrieval_quality` is 1.0 when at least one KB chunk was retrieved, 0.0 otherwise; `metadata_completeness` is penalised linearly per missing critical field. Weights and penalty live in `config.yaml`. |
| **Solve path** | The runtime path taken when triage finds no missing critical fields and the verifier's aggregate grounding score meets the threshold. Retrieve → reason → verify all run; `finalize_solve` emits the structured solution with `final_confidence = min(rubric_score, verifier_score)`. See [`../06-runtime-view/ticket-flow.md`](../06-runtime-view/ticket-flow.md). |
| **Supervisor** | The component that decides which worker runs next on each turn, based on the current `TicketState`. In Phase 3 the supervisor is implemented as two pure routing functions (`route_after_triage`, `route_after_verify`) plus three finalize sinks; LangGraph wires them as conditional edges. [ADR-005](../09-architecture-decisions/ADR-005-supervisor-topology.md) documents the per-edge LLM swap-in if eval shows the static thresholds underperform. |
| **Verifier** | A specialised LLM-as-judge agent that evaluates whether each claim in a proposed solution is grounded in its cited KB chunk. Returns a 0–1 grounding score and per-claim verdicts. |
